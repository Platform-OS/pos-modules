# UX review and redesign — 2026-10-29

Scope: every desk page (sign-in, queue, board, ticket, profile, ten settings pages) at 1440 and 390 px, light and dark, on the staging instance with the example host app. Tasks: TASK-32 to TASK-43.

## Method

Two independent assessments, run before and after the redesign, plus research:

- **Design review** with the [Impeccable](https://github.com/pbakaus/impeccable) critique method (Operate mode: Nielsen heuristics, cognitive load, persona walk-throughs, design specificity), the `ui-ux-pro-max` checklists and Anthropic's `frontend-design` list of template tells. Compared with the parallel build the team liked.
- **Technical audit** with the Impeccable audit method and detector, axe (WCAG 2.2 AA) in Playwright, and [Vercel's Web Interface Guidelines](https://github.com/vercel-labs/web-interface-guidelines).
- **Research** on helpdesk patterns in Linear, Front, Help Scout, Plain, Intercom, Zendesk and Missive, turned into a numeric spec (type scale, row heights, radii, palette roles).

## Scores

| | Before | After |
|---|---|---|
| Design review (Nielsen, /40) | 19 | 28 |
| Technical audit (/20) | 12 | 16 |
| axe serious/critical violations (16 pages × light/dark × desktop/phone) | 6 pages failing | 0 |
| Pages with sideways scroll at 390 px | 3 | 0 |

## What was wrong

1. common-styling styles only `text/email/password/url` inputs, so search, number, time and type-less inputs were 21 px browser boxes (white bars in dark mode).
2. Headings used common-styling's monospace heading font at marketing sizes (2.5 rem).
3. No icons, avatars or visual hierarchy; status as text-only rectangles; SLA as unicode triangles.
4. Rail counts never showed (the layout read the exported data from the wrong key).
5. Ticket page: stacked cards, radios for Reply/Note, a lone Send button; the composer could send twice and drop attachments chosen just before Send.
6. Destructive actions (bulk spam, revoke, decline, rotate webhook, turn off email) had no confirmation.
7. Dark mode: no `color-scheme`, pure black background, `theme_mode: dark` gave a half-dark page, toasts unreadable.
8. Every page loaded the Markdown editor, highlight.js and Uppy (about 400 KB of JavaScript).

## What changed

- Desk design layer in `pos-support.css`: type scale, one control recipe for every input type, button variants, pills, tables, toasts, focus rings, `color-scheme`, softer dark neutrals; still built from host `--pos-*` tokens (white-label).
- Shared partials: Lucide icon sprite, initials avatars, status/priority/SLA badges, relative times in the desk time zone, empty states, brand.
- Shell: sticky rail with sections, icons and counts; user menu with availability; skip link; per-page titles; drawer on phones.
- Queue: List/Board switch, attention chips, filters that apply on change, assignee filter, sort (SLA, priority, activity, newest, oldest), activity column, one-line rows, row-wide links, contextual bulk bar, cards on phones.
- Ticket: header band with previous/next and position in the queue (j/k), conversation timeline, collapsed automatic emails, email-like composer (From/To/Cc, Reply/Note tabs, single submit, Ctrl/⌘+Enter, draft warning), properties pane that saves on change, segmented priority.
- Board: bounded scrolling columns, card hierarchy, keyboard Move form, no drop into New.
- Settings: grouped left navigation, stacked forms, state pills, confirmations.
- Fixed while reviewing: merging or unmerging a ticket did not recompute its SLA, so overdue tickets lost their due date and sank to the end of the queue.

## Still open

- Command palette (⌘K) and a `?` shortcuts sheet.
- Group-by (priority/status) in the queue.
- Settings add/edit in a side panel; SLA durations as number + unit instead of minutes; Team page search.
- Toasts announce assertively (common-styling template); new live queue rows are not announced.
- Server-side duplicate protection for Send (the client sends once).
