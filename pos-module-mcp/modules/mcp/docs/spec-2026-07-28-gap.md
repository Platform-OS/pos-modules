# MCP `2026-07-28` — gap analysis & migration

**Status of this module:** implements **`2025-06-18`** and **`2026-07-28`**, negotiated
**per request**. A version-less or unknown request falls back to `2025-06-18`, so existing
clients are unchanged; `2026-07-28` behavior activates only when a client explicitly
negotiates it. This doc maps every change in the `2026-07-28` release to our engine, records
what shipped in the compat layer, and lists what remains.

> Source: the `2026-07-28` specification release announcement. Confirm exact field
> names / enum values against the final spec text before relying on them in production —
> where an enum was not yet pinned (e.g. `cacheScope`), we centralized the value so aligning
> it is a one-line change (`commands/protocol/cache_hint`).

## Why we fit the direction well

The headline change is **stateful/bidirectional → stateless request/response**. platformOS
pages are already independent, per-request POSTs authenticated by a bearer token on every
call — we never held an `Mcp-Session-Id` or server session. We also never implemented
roots/sampling/elicitation (the engine calls no LLM, spec §2), and we're plain
JSON-RPC-over-HTTP POST, not the now-deprecated HTTP+SSE transport. So the spec's biggest
moves are, for us, either no-ops or validations of existing choices.

## Change-by-change

| `2026-07-28` change | Our state | Action |
|---|---|---|
| **Stateless core** — retire `initialize`/`initialized` + `Mcp-Session-Id`; identity per request | Already stateless; bearer identity per request; no session held | ✅ Aligned. `initialize` kept for the transition; version now carried per-request via `_meta`/header |
| **Header routing** — `Mcp-Method` / `Mcp-Name` | **Shipped:** read + reconciled in `dispatch` (header may supply a missing value; a header that *disagrees* with the body → `-32600`) | ✅ Done |
| **Per-request version + capabilities in `_meta`** | **Shipped (version):** `commands/protocol/negotiate` resolves from `_meta.protocolVersion` → `MCP-Protocol-Version` header → `initialize` params → default | ⚠️ Partial — per-request *capabilities* in `_meta` are accepted but not yet consumed (we advertise a fixed capability set) |
| **Cacheable list results** — `ttlMs` / `cacheScope` | **Shipped:** added to `tools/list`, `prompts/list`, `resources/list`, `resources/read` **only** when `2026-07-28` is negotiated. Registry is deploy-invariant → long TTL; principal-scoped list → `cacheScope:"per-principal"`, else `"shared"` | ✅ Done (pending `cacheScope` enum confirmation) |
| **MRTR** — `resultType:"input_required"` + `inputResponses` (replaces elicitation/sampling/roots) | We never did elicitation/sampling/roots; our human-in-the-loop is operator-side | ◻︎ N/A now. If we ever need client-side input, MRTR is the shape — but **Tasks** (below) fits our approval flow better |
| **Tasks extension** — `io.modelcontextprotocol/tasks`, poll-based `tasks/get` + `tasks/update` | **Shipped:** an approval-gated action IS a task — `tasks/get` polls its status (self-scoped), `tasks/update` cancels it (agent-withdraw only; approve/reject stay operator-only, so the human gate can't be bypassed). Gated to 2026 clients; capability advertised in `initialize`; the pending `tools/call` response carries a `taskId` alias | ✅ Done |
| **Auth hardening** — RFC 9207 `iss`, `application_type` in DCR, issuer-bound creds, DCR→CIMD | We are a **protected resource** (serve `.well-known/oauth-protected-resource`, RFC 9728); tokens minted via our console, not DCR | ◻︎ Mostly N/A (AS-side). Track RFC 9207 `iss` if we ever front an authorization server |
| **Deprecations** — Roots, Sampling, **Logging** (12-mo window); HTTP+SSE transport | We never had roots/sampling; we're not SSE. We *do* implement `logging/setLevel` | ◻︎ Plan to phase out `logging/setLevel` within the window; comment added noting the deprecation |

## What shipped in this module (the compat layer)

- `commands/protocol/negotiate` — per-request version resolution (`_meta` → header → initialize params → default `2025-06-18`).
- `commands/protocol/cache_hint` — `{ttlMs, cacheScope}` from config; the single place to align the `cacheScope` enum.
- `rpc/dispatch` — negotiates once; reconciles `Mcp-Method` / `Mcp-Name` (supply-or-`-32600`); threads the cache hint into the list/read handlers; echoes the negotiated revision to `initialize`.
- `rpc/initialize` — returns the **negotiated** `protocolVersion` (not a hard pin) and advertises `_meta.supportedProtocolVersions`.
- `rpc/{tools_list, prompts_list, resources_list}` + `resources/read` — attach `ttlMs`/`cacheScope` only for a `2026-07-28` client.
- `config` — `supported_protocol_versions`, `latest_protocol_version`, tunable `cache` TTLs.
- `/mcp-health` — advertises `protocols_supported`.
- **Tasks extension** — `commands/rpc/{tasks_get,tasks_update}` + `commands/tasks/present` (provisional status map), routed in `dispatch` (2026-gated), capability advertised in `initialize`, `taskId` alias on the pending `tools/call` response.
- Tests — `conformance.test.mjs › protocol negotiation + 2026-07-28 compat` (precedence, unchanged-for-2025, cache-hints-gated, header reconciliation); `coverage.test.mjs › Tasks extension` (poll/cancel/self-approve-blocked, self-scoping, capability gating).

## Remaining checklist (prioritized)

1. **Per-request capabilities** *(small)* — consume client capabilities from request `_meta` rather than assuming the `initialize`-time set (required once stateless clients skip `initialize`).
2. **`cacheScope` + Tasks status/shape enum alignment** *(trivial)* — confirm the final spec enums; update `commands/protocol/cache_hint` and `commands/tasks/present` (both centralized for exactly this).
3. **Logging deprecation** *(later, within 12-mo window)* — announce + eventually remove `logging/setLevel`.
4. **Auth (AS-side)** *(only if we ever act as an authorization server)* — RFC 9207 `iss`, CIMD over DCR.

_Shipped since first draft: the **Tasks extension** (was checklist #1)._

## Non-goals / explicitly not doing

- HTTP+SSE transport (deprecated; we never offered it).
- Roots / Sampling (deprecated; the engine calls no LLM by design, §2).
